# Отчет об исправлениях по научному аудиту RCPSP

Дата: 6 октября 2026.

Основание: `SCIENTIFIC_CODE_AUDIT_RU.md`, 14 замечаний. Исправлены обнаруженные программные дефекты и изменены явно определенные части алгоритма/экспериментального протокола. Научные ограничения отмечены отдельно: изменение кода не доказывает оптимальность контроллера, новизну метода или его преимущество на общем классе задач.

## Результат работы

Создан единый экспериментальный протокол для baseline и meta с одинаковым бюджетом всех оценок расписаний. Результаты теперь содержат проверяемое расписание и полную информацию о запуске. Неуспешные процессы, тайм-ауты, неполные бюджеты, противоречащие эталонам результаты и неполное покрытие выборки не маскируются как успешные наблюдения.

Вознаграждение meta по умолчанию измеряет глобальное улучшение. Репликация больше не запускается только из-за улучшения слабой колонией собственного рекорда. Общая элита обновляет выбранную колонию после ее испарения; масштабы локального и элитного феромона согласованы.

Внесенные изменения меняют динамику поиска. Новые результаты относятся к новой реализации; старые CSV сохранены и не должны объединяться с новой серией.

## Статус каждого замечания

| № аудита | Замечание | Что сделано | Статус и предел исправления |
|---|---|---|---|
| 1 | Несопоставимые бюджеты | По умолчанию оба алгоритма получают одинаковый cap SGS, включая LS. Сохраняются фактические оценки, категории ACO/LS и причина остановки. Недоиспользованный бюджет из-за iterations отклоняется. | Исправлено для нового экспериментального драйвера. Прямые старые CLI остаются ручными запусками, а не строгим сравнительным протоколом. |
| 2 | Reward за собственный рекорд | Default reward привязан к глобальному улучшению; первая находка сравнивается с допустимым последовательным horizon. Репликация привязана к глобальному вкладу. Добавлен отдельный вариант quality. | Логическое несоответствие исправлено. Выбор лучшей политики reward требует экспериментов. |
| 3 | Неправомерный перенос гарантий UCB1 | Контроллер описан как эмпирическая UCB-подобная политика. Добавлены random, round_robin и discount. | Методологически уточнено; гарантия regret не доказана и не заявляется. |
| 4 | Драйвер запускает только baseline | Явный выбор алгоритмов, отдельные процессы, сохраненные эффективные параметры, среда и хеши. Запуск worker из снимка исходников. Порядок алгоритмов чередуется между seeds. | Исправлено; время процесса и поиска разделено. |
| 5 | Ошибки subprocess превращаются в результаты | Проверка returncode, JSON, расписания, бюджетов и истории. Сохранение логов и failure-артефактов. Итоговый exit code ненулевой при любом отказе. | Исправлено; ошибки остаются видны в summary, анализатор не усредняет их молча. |
| 6 | Отсутствующий CSV читается как Excel | По умолчанию используется существующий XLSX, лист PSPLIB. Поддержан CSV. Загрузчик стандартной библиотеки проверяет значения, дубликаты и границы. | Исправлено. Актуальность внешних эталонов остается ответственностью экспериментального протокола. |
| 7 | UB-lit трактуется как optimum | Раздельные gap_to_optimum, deviation_to_bks и gap_to_lb. KeepOPT не признается сертификатом. OPT устанавливается по явному полю либо LB=UB. | Исправлена семантика метрик; достоверность исходных границ самим кодом не доказывается. |
| 8 | Потеря количества колоний | Новые результаты структурированы. Legacy parser исправлен и отвергает неполный вывод. | Исправлено для новых запусков. Пропущенные значения старых CSV не выдумывались. |
| 9 | Драйвер не работает в текущем окружении | Совместимость с Python 3.9+, sys.executable, пути от __file__, отсутствие сторонних зависимостей. | Проверено в Python 3.9.6 и 3.13.3. |
| 10 | Baseline combo фактически none | Обе реализации используют общую combo-функцию и одинаковые признаки графа/нормализацию весов. | Исправлено; проверено совпадение значений и непостоянство эвристики. |
| 11 | Неравномерное элитное усиление idle arms и шкал | Idle arms не изменяются. Локальный deposit=tau0*H/C, elite использует относительный множитель той же величины. Initial boost — доля tau0. | Исправлено как явно определенная новая динамика. Ее преимущество не доказано. |
| 12 | Greedy ties зависят от номера работы | Случайный равномерный выбор среди точных максимумов в обоих алгоритмах. | Устранено предпочтение минимального номера в greedy ties. Полная инвариантность конкретной seeded траектории к переименованию не заявляется. |
| 13 | Переполнение score | Log-scores, нормализация относительно максимума, проверки конечности и явные диапазоны alpha/beta, tau0. | Исправлено. Значения вне поддерживаемого диапазона отклоняются. |
| 14 | Недостаточный экспериментальный набор и метаданные | Сохраняются сертификаты, история улучшений, параметры всех колоний, parent→child, pulls, оценки, снимки кода/входов. Добавлен описательный статистический анализ с проверкой покрытия и бюджетов. | Инструментальная часть исправлена. Полный benchmark, tuning/test разделение и содержательные абляции еще необходимы. |

## Проверки реализации

Тестовая команда:

```sh
.venv/bin/python -B -m unittest discover -s tests -v
```

Результат: **22/22 теста прошли**. Дополнительно тот же набор проверен интерпретатором `rcpsp/.venv/bin/python`, Python 3.13.3. Основной `.venv` использует Python 3.9.6.

Проверены:

- Точный перебор 40 случайных DAG по четыре работы, включая немонотонную нумерацию. Независимый oracle проверяет precedences и ресурсную нагрузку по временам начала, не вызывая производственные SGS/валидаторы. Лучший SGS по всем допустимым порядкам совпадает с точным оптимумом этих задач.
- Нулевые длительности, совпадающие начала/окончания, циклы и индивидуально недопустимые demands.
- Строгий бюджет и частичная последняя итерация; разделение расходов ACO/LS.
- Допустимость результатов обоих методов на всех 15 задачах; детерминированное воспроизведение meta при бюджете оценок.
- Нулевой reward за локальное улучшение, не улучшающее глобальный результат.
- Неизменность феромонов невыбранной колонии при elite reinforcement.
- Общая combo, alpha=beta=1000, случайные greedy ties, отклонение неподдерживаемых параметров.
- Масштабирование длительностей для combo и нормированных добавок baseline. Это не означает масштабную инвариантность min_duration.
- Контрольные режимы random/round_robin, discount, quality, независимые restarts и отключение элиты.
- Загрузка действительного XLSX, расчет разных gap-метрик и отклонение противоречивых reference bounds.
- Полный запуск драйвера, обнаружение поврежденного сертификата, аварий subprocess, timeout, недоиспользованного бюджета и неполного покрытия.

Проверки на конечном наборе входов не являются формальным доказательством корректности для всех RCPSP.

## Итоговая проверочная серия

Команда:

```sh
.venv/bin/python -B rcpsp/run_experiments.py --evaluations 100 --seeds 2 --output-dir experiment_results_v2/audit_fixes_verified
```

Каталог: `experiment_results_v2/audit_fixes_verified/`.

| Показатель | Результат |
|---|---:|
| Задач | 15 |
| Алгоритмов | 2 |
| Seeds на алгоритм/задачу | 2 |
| Успешных запусков | 60 из 60 |
| Оценок в каждом запуске | Ровно 100 |
| Суммарных оценок | 6000 |
| Оценок LS | 177, входят в общий бюджет |
| Пустых значений final_colonies | 0 |
| Нарушений проверенных ограничений расписаний | 0 |

`summary.csv` содержит сводку; `runs/*.json` — сертификаты и полные данные; `manifest.json` — происхождение результатов. `verification.json` подтверждает объем серии и replay.

Один meta-запуск повторно выполнен через сохраненные `sources/experiment_worker.py`, config и input. Совпали расписание, число и категории оценок, параметры/результаты колоний, события, config и хеши. Времена выполнения не сравнивались на равенство. Проверено также, что хеши текущих исходников совпадают с manifest этой итоговой серии.

Создан `analysis.json`. В этой короткой проверочной серии meta имеет меньшее среднее makespan на 10 задачах, равное на 3 и большее на 2. Средняя относительная разница средних meta−baseline по задачам составляет примерно −3.75%. Это **описание конкретной проверочной серии**, не доказательство преимущества: бюджет 100 и два seeds слишком малы, набор нерепрезентативен, параметры не прошли независимую настройку, абляции эффективности не выполнены. Bootstrap-интервал в файле также не устраняет эти ограничения.

## Проверка лимита времени

Дополнительная серия: `experiment_results_v2/audit_fixes_verified_time/`, одна задача, два алгоритма, time-limit=0.05 s и cap=10000 оценок.

Оба запуска успешны и остановились по времени. Время поиска составило примерно 0.0504 s для baseline и 0.0506 s для meta. Лимит кооперативный: операция, начатая до его достижения, завершается. При таком коротком лимите эти значения показывают работу механизма остановки, а не сравнительную скорость методов.

Проверочный запуск ограничен ресурсами поиска. Setup и запуск интерпретатора измеряются отдельно. Анализатор отвергает временное сравнение, если cap оценок сработал раньше deadline.

## Что остается для научной работы

1. Провести эксперименты на полном стандартном наборе или заранее обоснованной выборке. Локальные 15 задач сохранены как набор проверки реализации.
2. Разделить tuning/test и дать baseline сопоставимую настройку; для этого добавлен baseline-params-file.
3. Выполнить полноценные абляции: baseline+LS, фиксированный портфель, uniform/random вместо UCB, restarts вместо наследования, отключение elite и LS.
4. Проверить чувствительность к c, reward, discount, порогу репликации и elite-strength. Больший reward за пакет с большим расходом LS остается вопросом политики credit assignment; расходы теперь доступны в событиях.
5. Обосновать научную новизну и теоретические утверждения отдельно. Классическая теорема UCB1 к текущим обучающимся, взаимодействующим arms автоматически не применяется.
6. Проверить происхождение и актуальность эталонов для публикуемой серии; загрузчик не является доказательством истинности границ.

Работа по программным исправлениям и подготовке проверяемого протокола завершена. Полномасштабная проверка эффективности и теоретическое обоснование не подменялись короткими тестами реализации.
