# Протокол воспроизводимых экспериментов RCPSP

## Окружение и модель

Python 3.9 или новее. Решатели, драйвер, загрузчики эталонов, статистика и тесты используют только стандартную библиотеку. Установка сторонних пакетов не требуется. Поддерживается классический single-mode RCPSP с возобновляемыми ресурсами, целочисленными длительностями, нулевыми release times и минимизацией makespan.

Экземпляр после создания рассматривается как неизменяемый: не менять его durations/edges/demands напрямую, а создавать новый RcpspInstance. Характеристики графа кэшируются на экземпляре. Эвристическая «критичность» означает длину оставшегося пути по precedences, а не точную критичность с учетом ресурсов.

## Основной запуск

Из корня проекта:

```sh
.venv/bin/python -B rcpsp/run_experiments.py --evaluations 10000 --seeds 30
```

По умолчанию сравниваются baseline и meta на всех локальных `.sm`; каждый получает одинаковый бюджет всех SGS-оценок, включая LS. Iterations по умолчанию является заведомо достаточным защитным пределом, равным evaluations. Досрочное завершение по явному меньшему пределу iterations регистрируется как ошибка сравнения. Ограничение бюджета может оборвать последнюю итерацию, поэтому фактическое количество муравьев в последней итерации бывает меньше ants.

Драйвер использует тот же интерпретатор, запускает каждый поиск в отдельном процессе и вычисляет пути по расположению исходников. Запуск из другого рабочего каталога не меняет пути к стандартным задачам/эталонам. Явно переданные относительные пути разрешаются относительно рабочего каталога пользователя.

Порядок алгоритмов чередуется между seeds. При нечетном количестве seeds полной симметрии порядка нет; для сравнений времени предпочтительно четное количество повторений.

Для проверки одной задачи:

```sh
.venv/bin/python -B rcpsp/run_experiments.py --instance psplib/j301_1.sm --evaluations 100 --seeds 2
```

## Результаты и ошибки

Новый каталог содержит:

- `manifest.json`: настройки, фактическое окружение, порядок процессов, хеши исходников/входов/эталонного файла и извлеченные эталоны.
- `sources/`: снимок исходников. Worker действительно запускается из этого снимка.
- `inputs/`: снимки задач.
- `runs/*.config.json`: полная конфигурация каждого запуска.
- `runs/*.json`: времена начала, порядок работ, makespan, бюджет, разделение ACO/LS, история улучшений, параметры колоний и события контроллера/репликации.
- `runs/*.logs.json`: stdout/stderr.
- `runs/*.failure.json`: явное описание неуспешного запуска, если он был.
- `summary.csv`: статусы и числовые показатели.

Указанный `--output-dir` должен быть новым. Это предотвращает смешивание результатов с прежними экспериментами. Автоматически создаваемые имена содержат время UTC и случайный суффикс.

`status=success` означает, что worker завершился корректно, JSON прошел проверку, расписание повторно проверено драйвером, а бюджет и история согласованы. Несоответствие нижней границе или объявленному оптимуму считается ошибкой данных/результата и не попадает в успешные наблюдения. При любой ошибке драйвер заканчивается с ненулевым exit code, сохраняя результаты остальных запусков.

`search_runtime_sec` измеряет вызов поиска; `setup_runtime_sec` в JSON — загрузку задачи и создание решателя; `process_runtime_sec` включает запуск процесса и проверку результата драйвером. Последний показатель не следует называть чистым временем поиска.

Для воспроизведения отдельного запуска:

```sh
python /absolute/run-directory/sources/experiment_worker.py /absolute/run-directory/inputs/j301_1.sm --config /absolute/run-directory/runs/j301_1_meta_seed1.config.json --output /tmp/replayed_rcpsp.json
```

Использовать записанную версию интерпретатора. При одинаковом окружении, seed и бюджете оценок воспроизводятся расписание и решения контроллера; времена исполнения не обязаны совпадать. При ограничении времени число оценок и расписание не обязаны воспроизводиться точно.

## Эталоны и метрики

По умолчанию читается локальный `rcpsp/RCPLIB (Parameters and BKS).xlsx`, лист PSPLIB. Можно передать CSV с колонками `FileName,#Act,CPM,LBall,UB-lit,KeepOPT` и необязательной колонкой `Optimum`.

XLSX-загрузчик читает только значения таблицы, включая сохраненные cached values формул. Он не пересчитывает Excel. Отсутствующие обязательные числовые значения и ошибки Excel отвергаются. Источник и его SHA-256 фиксируются, но актуальность или истинность опубликованных границ самим загрузчиком не доказывается.

При наличии корректных LB и UB равенство LB=UB используется как сертификат оптимального значения. Явный Optimum является заявлением источника и должен иметь научное происхождение. Текст KeepOPT сохраняется как аннотация и сам по себе не признается сертификатом.

Метрики разделены:

- `gap_to_optimum_percent = 100*(C-OPT)/OPT`, только при установленном OPT.
- `deviation_to_bks_percent = 100*(C-UB-lit)/UB-lit`; отрицательное значение означает улучшение этого верхнего предела при проверенной допустимости расписания.
- `gap_to_lb_percent = 100*(C-LB)/LB`.

Для нулевого знаменателя процент не определен и сохраняется null. Отсутствующий эталон по умолчанию прекращает эксперимент до начала поиска. `--no-reference` явно разрешает запуск без gap-метрик; отсутствие эталона не маскируется.

## Контроллер и репликация

По умолчанию reward — относительное улучшение глобального рекорда, принесенное выбранной колонией за текущий пакет поиска. Первый результат сравнивается с известным допустимым верхним пределом sum(durations), не требующим отдельной SGS-оценки. Колония, улучшившая только свой рекорд и оставшаяся хуже глобального, получает 0.

Репликация разрешена только при глобальном improvement больше `--replication-threshold` и наличии оставшегося бюджета/места. Дочерняя колония наследует мутированные параметры и получает общую элиту; матрица феромонов родителя не копируется. `--replication-mode restart` заменяет наследование параметров независимой инициализацией для контрольного эксперимента.

Альтернативный `--reward-mode quality` использует precedence-only LB / C лучшего расписания текущей итерации. Репликация и в этом режиме остается привязанной к глобальному улучшению. Эти политики являются исследовательскими вариантами: никакая из них не объявляется теоретически оптимальной. Пакеты могут иметь разную стоимость из-за LS; число затраченных оценок записывается в каждом pull. Для исследования эффективности распределения следует анализировать этот расход, а не только число pulls.

`--selection ucb` — UCB-подобная эвристика для обучающихся, взаимодействующих arms. Гарантия regret классического стационарного UCB1 не заявляется. Доступны `--selection random` и `--selection round_robin`. `--discount 0.95` включает забывание: при каждом pull суммы наград и эффективные counts всех arms умножаются на discount, затем обновляется выбранный arm. Это не восстанавливает предпосылки UCB1.

Добавка локального феромона равна tau0*H/C, где H=max(1,sum(durations)), C=max(1,makespan). Elite-strength задает относительный множитель той же шкалы. Элита усиливает только выбранную колонию после ее испарения. Initial elite boost задается как доля tau0. Длительности, умноженные на положительное число, сохраняют H/C при ненулевом H; сама min_duration эвристика с выражением 1/(1+d) масштабно инвариантной не является.

В обоих алгоритмах combo вычисляется общей функцией. Выбор производится через log-scores и устойчивую нормализацию; точные равенства в жадной ветке разрешаются случайно. Диапазоны alpha/beta: [0,1000], tau0: (0,1]. Это явные ограничения API.

RNG для конструкции, LS-предложений и решения о запуске LS разделены. В менеджере также разделены инициализация параметров, выбор колонии, мутации и RNG каждой колонии. Переключение компонента не расходует случайные числа других компонентов непосредственно; различие феромонов и выбранных колоний все равно меняет последующие траектории.

## Абляции и настройка

Все варианты запускать в отдельные каталоги с одинаковыми evaluations и наборами задач/seeds:

| Вариант | Дополнительные аргументы |
|---|---|
| Baseline+LS | `--algorithms baseline --baseline-ls-iters 20 --baseline-ls-prob 0.5` |
| Фиксированный портфель | `--algorithms meta --disable-replication` |
| Равномерное распределение | `--algorithms meta --selection round_robin` |
| Случайное распределение | `--algorithms meta --selection random` |
| Перезапуски вместо наследования | `--algorithms meta --replication-mode restart` |
| Без общей элиты | `--algorithms meta --disable-elite` |
| Без LS | `--algorithms meta --disable-ls` |

Baseline также необходимо настраивать на отдельной tuning-выборке: полные параметры ACOParams принимаются через `--baseline-params-file params.json`. При этом файл заменяет baseline-настройки из остальных флагов; эффективные параметры полностью сохраняются в конфигурации каждого запуска.

Для сравнения времени добавить `--time-limit 10` и достаточно большой `--evaluations`, чтобы cap оценок не срабатывал раньше времени. Это кооперативный лимит: начатое построение/SGS завершится; небольшое превышение возможно. `--timeout` задает жесткий лимит всего subprocess и регистрирует timeout как ошибку, а не как успешное расписание. Анализатор отвергает временное сравнение, если хотя бы один запуск остановился по cap оценок.

## Статистика и границы выводов

```sh
.venv/bin/python -B rcpsp/analyze_results.py /absolute/run-directory
```

Создается `analysis.json`: распределения makespan по seeds, среднее/медиана/sample std, описательные bootstrap-интервалы средних и сравнение meta−baseline на уровне задач. Для итогового интервала единицей resampling служит задача, а не отдельный seed. Сравнение использует относительную разницу средних по задачам; отрицательное значение означает меньшее среднее makespan у meta.

Неуспешные, неполные и несопоставимые по бюджету данные отвергаются. Анализатор сравнивает два алгоритма внутри одного manifest; сравнение разных каталогов абляций требует отдельного анализа сопоставимости конфигураций.

Локальные 15 задач — набор для проверки реализации. Перед выводами для диссертации нужны полный стандартный benchmark либо заранее определенная репрезентативная выборка, раздельные tuning/test данные, достаточное число seeds, анализ чувствительности и абляции. Bootstrap на маленькой/смещенной выборке не исправляет ее нерепрезентативность. Новая реализация меняет динамику алгоритма, поэтому старые CSV нельзя объединять с новой серией.

## Тесты

```sh
.venv/bin/python -B -m unittest discover -s tests -v
```

Тесты включают независимый перебор времен начала небольших DAG, ресурсные ограничения и нулевые длительности, строгий бюджет, replay, глобальный reward, idle arms, численные границы, CSV/XLSX-эталоны, целостность сертификатов и обработку аварий/timeout.
